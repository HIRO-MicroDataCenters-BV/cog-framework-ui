What the Cognitive Framework is in VERGE
"The VERGE Cognitive Framework is a software asset developed in VERGE to facilitate the lifecycle management of AI models, enabling the AI model developers to register, train and serve their models in a unified way." — D5.2, p.85
① Register
Model registration via cf.pyfunc.PythonModel
② Train
Experiment tracking, TensorBoard, artifact storage
③ Validate
Pipeline stages, metrics logging, isolation via URIs
④ Serve
REST API via cf.ModelServing.deploy()
⑤ Infer
Real-time client via cf.InferenceClient()

Demo 2.4 · Secure & Trustworthy AI · Smart Mobility
Causal-RL + Formal Verification Pipelines
6 Test Cases · 3 Pipelines Completed
CF ran 3 pipeline configurations (6 test cases) training DRL and Causal-RL tram controllers and formally verifying them with PRISM. All artifacts stored and passed between pipeline stages via CF artifact URIs. Florence tram NGAP dataset used.
Model 1TD3 DRL Tram + LongiControl envs
Model 2TD3-INVASE CRL Causal-RL controller
VerificationPRISM DTMC Markov chain safety
DatasetGTSI Florence tram NGAP
MonitoringTensorBoard via CF
Key result from CF pipelines
CRL converged in ~250 episodes vs ~1,800 for DRL. CRL mean reward −433 vs DRL −817 on stochastic environments — 47% better generalizability.
Lesson (D5.2): FVT–CF integration required building REST adapter APIs from scratch. Middleware between specialized tools (PRISM) and generic platforms (CF) demands careful API design upfront.
Demo 2.5 · AI-driven Split Computing
DRL Split-Point Optimization Agent
DQN + PPO Completed
CF registered, tracked, deployed, and served a Deep RL agent that dynamically selects the optimal neural network split point between UE and edge server — minimizing inference latency, energy consumption, and SLA violations in real time.
Model 1DQN Deep Q-Network agent
Model 2PPO Proximal Policy Optimization
Input7-dim UE state (CPU/GPU/mem/bat/RSRP/RSRQ/SINR)
OutputOptimal NN split point (layer index 0–4)
Devices testedSmartphone · Tablet · Laptop · VR · IoT
Production endpointsplit-computing-prod
CF API calls used

CF capabilities proven in VERGE (from D5.2)

MLOps pipeline engine

  • Multi-stage Kubeflow pipelines (3 configs, 6 test cases in Demo 2.4)
  • CodeFlow Server IDE integrated with VS Code for pipeline authoring
  • Independent stage execution via CF artifact URIs
  • Docker containerized task execution
  • Artifact persistence enabling isolated task-level testing

Artifact & experiment management

  • Artifact storage for models, DTMCs, logs, verification outputs
  • MLflow experiment tracking — metrics, params, runs
  • TensorBoard for reward curves & training visualization
  • Model versioning and complete lineage tracking
  • Cross-stage artifact URI references (load by URI in isolation)

Model serving & inference

  • REST API endpoint deployment via KServe
  • InferenceClient for real-time UE split-point queries
  • Production monitoring dashboard (energy, latency, SLA)
  • Model signature inference for input/output specification
  • Endpoint tagging, versioning, and description metadata
