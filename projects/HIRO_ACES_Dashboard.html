HP3 Model — Technical Deep Dive (from loris_hyperparameter.ipynb)

GTAdam Algorithm

Gradient Tracking + Adam — distributed optimisation over a single-node graph (MPI simulated)

Hyperparametersβ₁=0.9 β₂=0.999 ε=1e-8
Step size0.001
Iterations1,000 per call
Search spaceα ∈ [0, 6], β ∈ [0, 6]
SurrogateGPR · RBF kernel · 20 restarts
IDW explorationδ = scaling (diversity bonus)
turn flagTrue = explore (IDW active) · False = exploit (final)

Per-Iteration Steps

1
Fetch KPI data · GET ACES Orchestration API · latest_geometric_mean_with_tuning_params
2
Transform data · Build kpi_window, alpha_beta_window tensors from API response
3
Infer via CF · POST hp3 KServe endpoint · turn=True (explore) on all but last iteration
4
Publish to NATS · JetStream publish {alpha, beta, timestamp, iteration, turn} → HP3 stream
5
Wait & repeat · Sleep 60s for scheduler to apply params · last iter: turn=False (exploit mode)

Hyperparameter Tuning — D-GLIS & GTAdam

D-GLIS: Distributed Global & Local Optimization

From ACES-EU/Self-hyperparameter-tuning · Python + MATLAB

  • Distributed Bayesian surrogate optimisation across multiple agents
  • IDW (Inverse Distance Weighting) diversity exploration bonus
  • Applied to MPC vehicle control (car_model.m, car_LTV_MPC.m)
  • Generalised to cloud resource scheduling in ACES
  • GTAdam = gradient tracking consensus + Adam momentum update
  • Supports multi-node MPI execution (faked to single-node via _FakeMPI for CF deployment)

CF Tuning Integration

How tuning plugs into the HIRO CF lifecycle

  • HyperParameterCalibrator registered as cogflow.pyfunc.PythonModel
  • Surrogate (GPR) rebuilt fresh per inference call from the rolling window
  • Model serialised with cogflow.pyfunc.log_model(code_path=["GTAdam.py"])
  • Signature auto-captured via cogflow.models.infer_signature()
  • 19 versions registered during development/testing in CF MLflow registry
  • Beale function used as KPI simulator for offline benchmarking

Integration Architecture — HIRO CF within ACES Platform

Data Flow: HP3 Closed-Loop

1 Prometheus scrapes cluster metrics → TimescaleDB (via CF REST API)
2 ACES Orchestration API aggregates gm_cpu_utilization with current α, β
3 KFP pipeline fetches 5–10 records → builds kpi_window + alpha_beta_window
4 HP3 KServe endpoint predicts new α, β (GTAdam + GPR surrogate)
5 Prediction published to NATS JetStream "HP3" stream
6 Workload Actions Manager (Go) consumes NATS message → applies α, β → loop continues

C-Suite Takeaways
🏗️
HIRO CF is the backbone of ACES data infrastructure The Cognitive Framework, developed entirely by HIRO, is the officially designated "central data orchestration layer" for the entire ACES platform — confirmed in project deliverable D4.5. All 11 partners' ML workloads route through CF.
🤖
Novel AI model (HP3) in production for autonomous CPU tuning HIRO developed and deployed the HyperParameterCalibrator — a distributed Bayesian optimisation model using GTAdam — that autonomously tunes CPU scheduler parameters in real-time, replacing manual cluster tuning. It runs as a live KServe service.
🔄
First closed-loop ML pipeline for edge-cloud resource optimisation The KFP hp3-tuning-pipeline creates a fully automated feedback loop: observe KPIs → predict parameters → apply via NATS → measure effect → repeat. This is a key ACES novelty for self-managing cloud infrastructure.
📊
Multi-model ML portfolio covering security, scheduling & anomaly detection HIRO contributed 4 distinct ML models across domains: hyperparameter tuning (HP3/GTAdam), workload classification (XGBoost/RF on Alibaba+AWS data), network security (KitNET on P4 switches), and cluster anomaly detection (Random Forest).
🔗
CF creates reusable IP across EU projects The same CogFlow library, model registry, and serving infrastructure developed for VERGE is now operating in ACES, demonstrating that HIRO's CF platform is a reusable, production-ready asset — not a one-off integration.
⚡
GTAdam algorithm is a research contribution with commercial potential The GTAdam distributed optimisation algorithm (gradient tracking + Adam) implemented in Python with disropt is novel academic work by HIRO/ACES. Combined with D-GLIS surrogate optimisation, this has potential for patent/commercialisation.
